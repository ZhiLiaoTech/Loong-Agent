# 代码评审

## 何时使用
- 用户提交 PR、diff 或要求 review 代码时

## 步骤
1. 先理解变更目标与影响范围
2. 检查正确性、边界条件、错误处理与可测试性
3. 关注命名、结构与可维护性
4. 按严重程度列出问题，并给出修改建议

## 输出格式
- **概要**：变更目的与总体评价
- **必须修改**：阻塞合并的问题
- **建议优化**：非阻塞改进项
- **测试建议**：需要补充的测试场景
