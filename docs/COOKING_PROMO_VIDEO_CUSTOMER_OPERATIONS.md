# 自动炒菜机视频 Suite 客户操作手册

## 1. 投递视频

每次炒菜建立一个独立批次目录，放入 2～4 路普通网络摄像头视频。建议命名包含机位，例如 `front.mp4`、`top.mp4`、`side.mp4`。文件复制完成后再创建空文件 `_READY`；不要边录制边放 `_READY`。

```text
inbox/
  20260905-lunch-001/
    front.mp4
    top.mp4
    side.mp4
    intake.json        # 可选
    machine-events.jsonl # 可选
    _READY
```

未提供机器事件时系统使用画面/音频启发式并强制人工审核。不要上传未获授权的人脸、音乐、Logo 或客户隐私素材。

## 2. 处理与审核

1. 确认批次显示 ready/consumed，而非 incomplete/invalid。
2. 在 Studio“视频审核”确认多机位同步；低置信度时人工调整 offset。
3. 浏览事件和候选镜头，修改机位、入点/出点、字幕或删除片段。
4. 驳回/返修必须填写原因；批准当前修订后才能渲染正式成片。
5. 检查 quality report 全部硬门禁通过，再下载成片用于发布。

## 3. 常见问题

- 文件一直 waiting：确认 `_READY` 或等待文件稳定 60 秒，检查视频是否仍在写入。
- 某一路缺失/损坏：重新导出该机位并用新批次投递，不覆盖已消费目录。
- 同步不准：选择清晰的共同动作或声音设置人工 offset；不要强行批准跳帧画面。
- 无可用镜头：清洁镜头、减少蒸汽遮挡、检查顶视/正视机位和照明后重拍。
- 渲染失败：记录 job id、时间和错误码交给运维，不发送原片或密钥到聊天群。

## 4. 删除与保留

保留期未由客户书面确认前系统只做 dry-run。legal hold 作业不会自动删除。删除报告应由授权人员复核；发布成片前确认已有备份和版权留档。

## 5. 支持信息

报障提供：tenant、job id、发生时间、阶段、错误码、浏览器/客户端版本。不要提供预签名链接、访问密钥、完整审计文件或未脱敏媒体。
